# 市販税務ソフトとの機能比較・ギャップ分析・拡充ロードマップ

本書は、`TaxReturnApplication-Dioxus` を**市販の税務申告ソフトウェア（freee、マネーフォワード クラウド確定申告、やよいの青色申告、国税庁確定申告書等作成コーナー等）に匹敵・凌駕する水準へ引き上げるための機能比較、ギャップ分析、および段階的開発ロードマップ**です。

---

## 1. 市場ポジションと当アプリケーションの固有の強み

### 1.1 主要市販ソフトウェアの分類
現在市場で広く使われている確定申告ソフトウェアは、大きく3つの系統に分かれます。

1. **クラウド型SaaS（freee、マネーフォワード クラウド確定申告）**:
   - *特徴*: 銀行・クレカAPI自動同期、スマホアプリ対応、自動仕訳提案。
   - *課題*: 月額/年額の継続課金（毎年1万〜3万円超）、ネット接続必須、個人財務データの外部クラウド預託、仕様変更・UI改変への強制追従。
2. **インストール型パッケージ（やよいの青色申告、勘定奉行等）**:
   - *特徴*: 豊富な帳票、税理士標準の複式簿記機能、高速入力。
   - *課題*: Windows専用が多い、OS更新ごとの有償アップデート、独自バイナリ形式によるデータ囲い込み（ベンダーロックイン）。
3. **公的システム（国税庁 確定申告書等作成コーナー / e-Tax）**:
   - *特徴*: 無料、最新税制に完全対応、直接送信可能。
   - *課題*: 会計帳簿・日々の記帳機能がない（決算書や仕訳帳は別途自前で用意して数字だけ転記する必要がある）、UIが毎年変わり入力が煩雑。

### 1.2 当アプリケーション（TaxReturnApplication-Dioxus）の現状の強み

| 観点 | 当アプリケーションの強み | 市販クラウドソフトとの対比 |
|---|---|---|
| **プライバシー & セキュリティ** | **100% ローカル完結**。外部ネットワーク通信を一切行わず、機密情報が流出するリスクが原理的にゼロ。 | 銀行認証情報や取引明細が外部サーバーに保管されるリスクが存在。 |
| **ランニングコスト** | **完全無料・永年利用可能**。サブスクリプション料金なし。 | 毎年1万〜3万円程度の維持費が恒久的に発生。 |
| **オープンなデータ仕様** | **JSONフォーマット**。Gitによる差分管理やバックアップ、スクリプトによる自由な解析・一括加工が可能。 | 独自DBやプロプライエタリ形式でエクスポート・移行が困難。 |
| **パフォーマンス・リソース** | **Pure Rust 単一バイナリ**。起動が瞬時（1秒未満）、メモリ消費数十MB程度、ElectronやWebブラウザのような重厚さがない。 | ブラウザベースで動作が重く、オフラインでは利用不可。 |
| **クロスプラットフォーム** | Windows, macOS, Linux すべてで単一バイナリ動作。 | Linux非対応や Mac版の機能制限が多い。 |

## 3. データ保存形式のアーキテクチャ比較分析（独自JSON vs GnuCash SQLite vs Beancount）

本アプリケーションのデータ保存形式をどのように進化させるべきか、家計簿・オープンソース会計で著名な **GnuCash (SQLite)**、**Beancount (Plain Text Accounting)**、および **現行の独自JSON形式** を比較分析します。

### 3.1 各保存形式の特性比較

| 評価軸 | 現行: 独自JSON (年度別分割) | GnuCash互換 (SQLite3 単一ファイル) | Beancount (プレーンテキスト) |
|---|---|---|---|
| **ファイル管理** | 年度ごとに1ファイル (`{year}.json`) | **全期間が1ファイルに集約 (`.gnucash`)** | 1ファイル（または複数 `.beancount`） |
| **他ソフト互換性** | ✕ 完全独自形式（他ソフト互換なし） | **◎ GnuCash デスクトップで直接閲覧可能** | **◎ Beancount / Fava で直接閲覧可能** |
| **大量データ性能** | △ 件数増加で全件パース・保存が重くなる | **◎ B-TreeインデックスとSQLで超高速** | △ 数万件を超えるとパース負荷が増大 |
| **トランザクション安全性** | ◯ 一時ファイル経由のアトミック置換 | **◎ SQLiteの完全なACIDトランザクション** | △ 上書き保存（行単位アトミック性なし） |
| **Git / テキスト差分** | ◯ JSONテキスト差分が可能 | ✕ バイナリDBのため差分は見えない | **◎ 世界最高水準（行単位で完全な差分）** |
| **複合仕訳の表現力** | ✕ 1借方 : 1貸方のみ | **◎ `transactions` + `splits` で標準対応** | **◎ 複数行のPostingで標準対応** |
| **日本の税務メタデータ** | ◎ 専用設計で完全最適化 | △ `slots` 属性テーブルに格納が必要 | △ タグやメタデータ行に格納が必要 |

### 3.2 GnuCash SQLite のアーキテクチャ詳細
- **構造**: `books`（帳簿管理）、`accounts`（階層勘定科目ツリー）、`transactions`（取引ヘッダー）、`splits`（借方・貸方の各明細行）、`slots`（任意のキー・バリュー拡張属性テーブル）等からなるリレーショナルスキーマ。
- **長所**:
  1. **単一ファイル完結**: 1つのSQLiteファイル（例: `accounting.gnucash`）をバックアップ・移動するだけで全履歴が保全される。
  2. **GnuCashエコシステム**: GnuCashで開いて、詳細な試算表、多通貨換算、有価証券ポートフォリオ管理などを相互利用できる。
  3. **複合仕訳（Split）の標準化**: 手数料差引や複数口座への按分など、多対多の仕訳を自然に表現可能。
- **課題**: GnuCash固有の型仕様（GUIDの16進文字列、有理数 `value_num`/`value_denom`）の実装と、日本の税務情報（青色特別控除区分や家事按分設定）を `slots` テーブルへ適合させる設計が必要。

### 3.3 Beancount (Plain Text Accounting) のアーキテクチャ詳細
- **構造**: 人間が読めるシンプルなテキスト形式。
  ```beancount
  2026-01-05 * "家賃振込" "1月分賃料"
    Assets:Bank:SMBC            165000 JPY
    Income:Sales               -165000 JPY
  ```
- **長所**:
  1. **Gitとの究極の親和性**: 誰が・いつ・どの仕訳を変更したかをGitのコミット履歴で1行単位で追跡可能。
  2. **Fava Web UI**: オープンソースのWeb会計ダッシュボード「Fava」を起動して極めて美しいグラフやB/S・P&Lを即座に表示可能。
- **課題**: GUIデスクトップアプリから特定の仕訳をID指定で修正・削除する際、テキストファイルの構文木操作が発生し、SQLiteに比べて整合性管理のコストが高い。

### 3.4 推奨されるストレージ進化戦略（ハイブリッド・単一ファイル化）
ユーザーの**「単一ファイルで管理したい」「GnuCashのSQLite形式が良い」**という要望を最も美しく実現するため、以下の**ハイブリッド・ストレージ戦略**を採用します。

1. **プライマリDBの単一ファイルSQLite化**:
   - アプリケーションの内部永続化エンジンを、年度別JSONから **単一のSQLiteファイル（`tax_return.sqlite` / `tax_return.gnucash`）** へ移行。
   - GnuCash標準テーブル（`accounts`, `transactions`, `splits`）と互換性のあるスキーマ構造を採用し、単一ファイル内に全年度・全仕訳を保持。
2. **相互運用レイヤー（GnuCash & Beancount インポート/エクスポート）**:
   - **GnuCash相互運用**: GnuCashで作成したSQLiteファイルを本アプリで直接開き、確定申告書Bや青色決算書PDFを生成。
   - **Beancountエクスポート**: 本アプリの仕訳データを `.beancount` テキスト形式としてワンクリック出力（Gitで管理したい、Favaで見たいユーザーの要望を満たす）。
   - **旧JSONからの自動マイグレーション**: 既存の年度別JSONを自動検知して単一SQLiteへ一括インポートする移行機能を提供。

## 5. 各フェーズの詳細実装計画

### Phase 1: 複式簿記・決算基盤の強化（実装完了 ✅）
- **勘定科目カスタマイズ**:
  - 標準青色申告科目（広告宣伝費、接待交際費、外注工賃等）の追加、およびユーザー定義カスタム科目 `AccountCode::Custom(String)` に対応。
  - 科目マスタ `AccountDefinition`（名称、資産/負債/純資産/収益/費用、補助科目リスト）を管理。
  - 補助科目（銀行名、クレジットカード名、主要取引先など）の自由追加・削除、仕訳入力・一覧バッジ表示に対応。
  - 同一勘定科目間でも補助科目が異なる資金移動振替仕訳（例: 普通預金A → 普通預金B）を許容。
- **家事按分機能**:
  - 経費科目（地代家賃、水道光熱費、通信費など）ごとに「事業利用割合（0〜100%）」を設定可能。
  - 「家事按分仕訳を一括生成・反映」ボタンで、個人負担分（事業主貸）への振替仕訳（12月31日付）を自動生成。再実行時の安全な更新にも対応。
- **年度繰越処理**:
  - 前年度末の資産・負債残高を翌年の期首残高として引き継ぎ。
  - 翌期首元入金（$\text{前期末元入金} + \text{当期純所得} + \text{事業主借} - \text{事業主貸}$）を自動算出し、1月1日付の開始仕訳を自動計上。
  - 翌年度作成・データ引き継ぎ後に自動で画面切り替え。
- **決算・設定画面 (ClosingPage)**:
  - 勘定科目・補助科目設定、家事按分設定・実行、年度繰越処理の3タブを持つ専用画面を新設。

### Phase 2: 減価償却・所得控除の完全対応（実装完了 ✅）
- **固定資産台帳**:
  - 資産名、取得日、取得価額、耐用年数、償却方法（定額法 / 一括償却3年 / 少額資産特例即時償却）、事業専用割合を登録。
  - 年末減価償却費・事業専用割合による経費算入額を自動計算し、12月31日付の減価償却仕訳（減価償却費・事業主貸 / 工具器具備品等）を一括生成・仕訳帳へ自動反映。決算書第3面「減価償却費の計算」欄の全数値を正確に算出。
- **所得控除マネージャー**:
  - 社会保険料控除、国民年金基金・小規模企業共済等掛金控除（iDeCo含む）。
  - 生命保険料控除（新・旧一般生命保険、介護医療保険、新・旧個人年金保険の法定算式上限計算、合算上限12万円）。
  - 地震保険料控除（旧長期損害保険併用計算、上限5万円）、医療費控除（10万または総所得5%足切り）、寄附金控除（ふるさと納税）。
  - 配偶者控除・配偶者特別控除（本人所得制限逓減対応）、扶養控除（一般38万、特定63万、老人同居58万、老人別居48万）。
  - 障害者控除、ひとり親控除（35万）、寡婦控除（27万）、勤労学生控除（27万）。
- **住宅ローン控除・税額控除**:
  - 住宅借入金等特別控除額、その他の税額控除（配当控除等）を算出所得税額から直接差し引き、差引基準所得税額に対して復興特別所得税（2.1%）および申告納税額を精密計算。
- **UI & 帳票連携**:
  - 「決算・設定」画面に第4タブ「固定資産台帳・減価償却」を新設。
  - 「帳票」画面に「所得控除・税額控除の設定」フォームおよび確定申告書B計算結果・控除内訳テーブルを統合。

### Phase 3: 単一ファイルSQLite化 & GnuCash / Beancount相互運用（実装完了 ✅）
- **単一ファイルSQLite永続化 (`rusqlite`)**:
  - 全年度の仕訳、勘定科目マスタ、補助科目、納税者情報を単一のSQLiteデータベース（例: `tax_return.sqlite` / `tax_return.gnucash`）に集約。
  - 1ファイルを持ち運ぶ・バックアップするだけで全年度のデータを安全に保持。
  - SQLiteのB-TreeインデックスとACIDトランザクションにより、数十万件の仕訳でも瞬時に検索・集計。
  - `rusqlite` の `bundled` 機能によりCコンパイラで静的リンクし、外部依存ゼロの単一バイナリ配布を維持。
- **GnuCash互換スキーマ連携**:
  - GnuCashの標準テーブル設計（`books`, `commodities`, `accounts`, `transactions`, `splits`, `slots`）に準拠したデータ構造をサポート。
  - GnuCashで入力・管理されたSQLite形式ファイルを本アプリで直接開き、日本の確定申告書Bや青色決算書を生成可能に。
  - 1つの取引（`transactions`）に複数の借方・貸方明細（`splits`）を保持できる複合仕訳（諸口仕訳）を内部データモデルとして完全サポート。
  - 任意のファイルパスへGnuCash互換SQLiteデータベースを直接ワンクリック書き出し可能。
- **Beancount プレーンテキスト入出力**:
  - 本アプリの仕訳データを `.beancount` テキスト形式としてワンクリックでエクスポート・インポート。
  - 日本語勘定科目をBeancount標準階層（`Assets:Bank:...`, `Expenses:Business:...` 等）へ双方向自動マッピング。
  - Gitで1行単位の差分管理を行いたい開発者や、Web UIツール「Fava」と連携したいユーザーに究極のポータビリティを提供。
- **既存データからの自動移行**:
  - 旧バージョン（スキーマv1〜v3）の年度別JSONファイルを自動検出し、単一SQLiteへ一括コンバートするマイグレーション機能。
  - 読み込み時はSQLite優先（未登録ならJSONから自動インポート）、保存時はSQLite主書き込み＋JSONバックアップのデュアルライトで安全性を担保。
- **UI統合 (ClosingPage 第5タブ)**:
  - 「決算・設定」画面に「データベース & 外部連携」タブを新設。
  - SQLite接続状況、登録年度一覧、総仕訳数、データベースファイルサイズ等のリアルタイム診断表示。
  - ワンクリック旧JSON移行ボタン、GnuCashエクスポート、Beancountエクスポート・インポートUIを提供。

### Phase 4: 公式帳票オーバーレイ & e-Tax XML出力（実装完了 ✅）
- **国税庁公式PDFテンプレート印字**:
  - 青色申告決算書（全4面）:
    - 第1面: 損益計算書（売上、仕入、経費科目別内訳 [11]〜[31]、専従者給与、青色申告特別控除 [44]、所得金額 [45]）

    - 第3面: 減価償却費の計算（固定資産台帳からの取得価額・償却方法・本年償却費・事業専用割合・必要経費算入額・期末残高） & 地代家賃の内訳（支払先・支払額・事業割合・必要経費算入額）

  - 税務署へそのまま持参・郵送して正式受理される実務提出品質を実現。
